## 1. Fixes (engine)

**H1: under `complete`, the guard space no longer depends on the observations** (programs mode).

*The rule.* If any observation of the capability is at a `complete` subject:
- The guard space is every (Q, T) pair told about a node of the acquisition component.
- It also contains one pair absent from the component (`absent absent`). On that pair, `not:` is
  the identity filter.
- If this exceeds MAX_GUARDS (8), the space stays as proposed, and the status is **capped at
  provisional**. This is recorded as `scan.guard_gap`.

*Why it is sound.*
- Take any hidden program in the grammar (size ≤ 5, with steps over the component's relations).
- A guard on a pair that is absent from the component is constant there:
  - an `is:` guard empties its clause, so the clause can be dropped;
  - a `not:` guard is the identity filter, so it can be swapped for `not:absent:absent`.
- So there is an equivalent program, the same size or smaller, inside the scanned space. It
  behaves identically on the component.
- The verifier showed that the in-space argument holds: 0/236 wrong.
- **Remaining assumption:** the truth is a grammar program of size ≤ MAX_SIZE over the
  component, or it uses an offered capability. It is stated, and it does not depend on the data.
