# G59: the learning-amortization qualification gate (Roadmap II G59)

Registered before the run (2026-11-27). This text is final at the commit that adds it, before any G59
registered run; results are appended below §12 only. The registered run starts only with
`/workspace/REGISTERED_RUN.lock` in place (`benchmarks/g59_registered.sh` records its create and delete
times), with no other CPU work of ours beside it; every arm run is written to disk when it finishes.
Instrument: learning-amortization 70297af (`/workspace/vendor/learning-amortization`, pinned, unmodified).

## 1. Why

G58 removed library-size cost; the invariants analysis (branch invariants-analysis, 29557fd, I3) found
the remaining blocker for bounded overhead: fact recall that still grows ~N^1.08–1.10 with unrelated
facts, because the G57b exact recall filter scans posting lists of every code sharing a bit with the
query. Under Prop 10 of the instrument, any overhead linear in unrelated state rules out positive
long-run A, whatever the constant. G59 (a) makes recall touch only codes near the query, (b) folds in
verify-33565b0, and (c) runs the pre-registered qualification gate, whose failure triggers the switch
rule (§8).

## 2. Mechanism: `--partitioned` (requires `--routed` and `--incremental`) and serve changes

The flag changes no reply and no state byte (§3).

**2a. Partitioned exact recall (`Memo.recall_partitioned`).** A triple t adds a name x to the recall
of (s, r) iff it passes (2|p∧q| > |p|) and p ⊕ q = c_x (x's role-2 code, ≤ 16 bits). Then |p ⊕ q| ≤ 16,
so m = |p∧q| ≥ (|p| + |q| − 16)/2. p lies in the union of t's three codes (≤ 16 bits each), so two of
them have |X∧q| ≥ k = ⌈(m_min − 16)/2⌉. Each code's ascending bits are split into PAIR_GROUPS = 4
consecutive groups and every pair inside a group is indexed; a code with |X∧q| ≥ k ≥ 5 has two of
those bits in one group (pigeonhole), so one of its indexed pairs is a pair of q's bits. Candidates:
every triple with two codes in H = {indexed codes hit by a pair of q's bits with |X∧q| ≥ k} (joined
through by_sr / by_s∩by_o / by_rel∩by_o), plus every packet with |p| < SMALL_PART = 42. When k < 5
(`part_threshold` None) the G57b filter is used. The query never visits a posting list of a code that
shares fewer than two bits (in one group) with q.
**2b. Stamps in increasing order** (`Memo.stamp` moved to the end when bumped) so the routed review
stops at the first old stamp instead of scanning every relation.
**2c. Seeds index in step** at the end of every call (the call that wrote pays).
**2d. Snapshot `gc.freeze`.** After a `--partitioned` snapshot the long-lived state is moved to the
permanent GC generation (young generations collected first); `close` unfreezes. No reply or state
depends on it (tested with the collector off).
**2e. Proportional maintenance (serve, `PACKETLM_SNAPSHOT_RATIO` / `Server(snapshot_ratio=q)`, off by
default).** With q > 0 a snapshot is taken when ≥ 64 calls are journaled and the journal holds ≥ q × the
snapshot's bytes (log compaction; reopening replays at most ~q × the snapshot), and the periodic full
validation happens at those snapshots instead of every 64 calls. Snapshot plus validation work per call
is then bounded by the call's own journal bytes. Cost: detection latency of an index corruption grows
with the state (corruption is still caught before any snapshot is written). Replies and final state are
identical (tested).
**2f. verify-33565b0 folds.** Med: a call whose `_validate` ran the full checks does not repeat them in
its snapshot (`checked_call`); per-code bits in `ix_check` come from the `_code_bits` memo; maintenance
is charged in part S (§4). Low 1: `Engine.cache_check` compares the G58 capability index (entries,
offered order and primitives, by-first lists, dependency map) and seeds index against fresh builds at
every full validation and snapshot (not the review fingerprint map, whose entries may legitimately lag;
the audit checks it in tests). Low 2: a mutation whose test run times out counts as killed. Low 3:
registered timing runs use 4 workers (was 7–8). INFO: dead `_lib_key` removed; `--routed` detects a
corrupted capability up to 6 calls late (stated, not changed); G58.md's 5.48 paragraph is corrected in
G58.md §12 by a dated erratum (charged with the duplicate check, routed R64_1024 = 7.48 [6.12, 8.39],
above the 7.33 half-threshold — the registered stop rule was on task CPU and is unchanged).

## 4. Registered part S: padding-growth exponent (`benchmarks/g59_scale.py`)

- Protocol of G57 part S: N unrelated padding facts over 20 relations plus N // 500 one-step padding
  capabilities, then a fixed 10-task workload; padding and an uncharged snapshot before the window.
  N ∈ {0, 1000, 16000, 32000, 64000}; **fresh seeds 291–297**; arms r0 = the 33565b0 checkout
  (subprocess), r = this commit with G58 flags, k = + `--partitioned`; flags `--answers --bounded --lean
  --indexed --incremental --routed`. 4 workers.
- Per-task costs: **task** = workload call CPU per task; **charged (fixed)** = task + journaled calls
  per task × snapshot CPU / 64 (the snapshot is the full validation; run once per call since §2f);
  **charged (proportional)** = task + journaled calls per task × snapshot CPU / max(64, q × snapshot
  bytes / journal bytes per call), q = 1.0; **work** = number of Python and C function calls the
  workload makes (counted with `sys.setprofile` in a forked copy after padding; uncharged).
- Exponent α(N1→N2) = ln(bootstrap mean of per-seed ratios T(N2)/T(N1)) / ln(N2/N1), 95% percentile CI
  (5000 resamples, seed 0), for 16k→32k, 16k→64k, 32k→64k.
- **Primary (registered): bounded iff the upper CI of α_task(k, 16k→64k) < 0.2.**
- **Co-primary (registered): bounded-charged iff the upper CI of α_charged-prop(k, 16k→64k) < 0.2.**
- Secondary (reported, same 0.2 reading): α_work(k), α_charged-fixed(k), the same for r and r0; R0_N,
  R1k_N; snapshot and padding CPU. Material vs r0 (anti-circling): k's 16k→64k ratio upper CI ≤ half
  of r0's point ratio.
- Guards: replies and final state of r and k equal r0's at every (seed, N); workload answered identically
  at every N; no snapshot in the window; r0 is a clean 33565b0.

## 6. Registered gate (`benchmarks/g59.py`, instrument 70297af)

**6a. Qualification of positive A (overall): PASS iff all of**
- Q1 comp: A(Ck+maint‖Bk) lower CI > 0;
- Q2 every curriculum: 0 wrong-qualified sealed answers (and transfer), 0 retention changes, sealed
  correct of C ≥ B's;
- Q3 unrel: A(Ck+maint‖Bk) lower CI > −0.949 (half of G58's L3r −1.898: the unrelated penalty halved);
- Q4a comprep: A(Ck+maint‖Bk) lower CI > 0; Q4b mixed: A(Ck+maint‖Bk) lower CI > 0.
Otherwise HOLD. Primary contrasts per curriculum: Ck+maint‖Bk, Ck+maint‖Pk+maint, Ck+maint‖Cr+maint.
**6b. Censoring.** For Ck‖Bk per curriculum: censored counts, the direction (exact / lower bound /
upper bound / undetermined), the censoring interval (Prop. 9: [A_rec, 1] if only B is censored,
[−∞, A_rec] if only C, undetermined if both), and A on the matched subset (descriptive only).
**6c. Per search-depth stratum.** A(Ck‖Bk) task-only per stratum of B's searched depth (2/3/4/5), each
curriculum but unrel; a stratum qualifies positive iff its lower CI > 0. **Deepest-first** holds iff in
comp the deepest stratum has the highest point A and, if any comp stratum qualifies, the deepest does.
**6d. Work vs time.** 1 − A_cpu = (1 − A_work) × ρ, ρ = per-op cost ratio, for work ∈ {evaluations,
executions, row_ops}, vs B and vs P, with CIs (identity residual reported).
**6e. Secondary resources** (not primary): A on evaluations and on teacher lines, same instrument.
**6f. Accumulation threshold / rate ratio (James).** On long (and every curriculum, reported), per family
f: y_f = ln(C_f/B_f) (CPU), w_f = ln(W^C_f/W^B_f) (evaluations), o_f = y_f − w_f. Savings-compounding
rate s = −slope(w), overhead-growth rate o = slope(o), slope(y) = o − s; seed-bootstrap CIs. Predicted
crossover family f* where the fitted y reaches 0 (none if slope(y) ≥ 0). Classification on long's
A(Ck‖Bk) and its per-task trend β: crosses zero (A lower CI > 0), plateau below zero (A upper < 0, β CI
holds 0), diverging below zero (A upper < 0, β upper < 0).
**Guards:** Xk = Xr replies and state bytes for every role and seed; 0 wrong-qualified in C; instrument
pinned and unmodified; source unchanged during the run.

## 7. Predictions (dev data only, not evidence; dev seeds 901–941 gate, 971–983 part S)

- Part S (dev seeds 981–983, this code): α_task(k, 16k→64k) = 0.37 [0.29, 0.44] → **bounded predicted
  NOT to hold** (upper ≥ 0.2). α_charged-prop = 0.36 [0.28, 0.43] → **not bounded** (the proportional
  period at 64k is ~50,000 calls, so maintenance adds almost nothing; the task term decides).
  α_work (function calls) = 0.10 [0.098, 0.107] → bounded in work (secondary), but rising with N
  (16k→32k 0.07, 32k→64k 0.13): a small linear term remains (codes sharing an indexed pair with the
  query; ~1/N_keys of all codes) plus the residual O(L) of the N/500 padding capabilities. The time
  exponent is ~3.5× the work exponent: per-operation cost grows as the pair and fact hash tables outgrow
  the CPU caches (same call counts, slower calls in the dev profile). α_charged-fixed = 1.06 [1.00, 1.14]
  (snapshot CPU α = 1.14: a snapshot serializes and checks the whole state). Material vs r0: yes
  (earlier dev, r0 α_task = 1.31 [1.13, 1.54]; k's 16k→64k ratio ≈ 1.7 vs r0's 6.1).
- Gate: **HOLD; switch rule triggered** (dev comp A(Ck+maint‖Bk) ≈ −1.07, comprep −0.86, mixed −0.63,
  unrel −1.67, long −1.04). Q2 holds. Ck‖Cr ≈ 0 on comp (recall is not the comp bottleneck: states are
  small).
- Strata: deepest-first **holds** in comp (the deepest stratum has the highest point A in every dev
  run: comp 901–902 stratum 5 −0.58 vs −0.97…−1.61; comp 951 +0.02 vs −0.76…−1.10; comprep/mixed/long
  stratum 5 −0.11/−0.10/−0.34 vs ≤ −0.6 elsewhere). Stratum 5 sits near zero; with 7 seeds its lower CI
  is predicted **below 0** (not qualified), but this is the least certain prediction. Strata 2–4: not
  qualified, A ≈ −0.6 to −1.7.
- Work vs time: A_work(evaluations) ≈ +0.84 (C needs ~6× fewer evaluations than B) while A_cpu ≈ −1.07:
  ρ ≈ 12 — the utility problem. Dev profile of one comp C vs B arm: C runs 137 scans with 1.5 M scan
  steps vs B's 38 scans and 0.18 M: C's search explores a primitive set that grows with every accumulated
  relation, and the scan's visited counts are state bytes (G58 §12), so no exact mode may skip them.
- Secondary: A(lines) ≈ +0.45 comp; ≈ 0 vs P.
- Rate ratio on long: slope(y) > 0, o/s ≈ 1.9, **no crossover predicted (N* = none)**; classification
  diverging below zero.

## 8. Switch rule (James; G58 §8, registered here)

If G59 cannot qualify positive learning amortization under §6a (verdict HOLD), that is evidence that the
limitation is the core representation; the next step is an alternative mathematical approach evaluated
with the same instrument and verification setup, not further optimization of this engine. G59 does not
start that evaluation; it reports the trigger and the evidence that would inform it.
