# G46 — longitudinal continual learning (pre-registered)

Written and committed before `benchmarks/g46.py` produces any result.
The engine source is frozen for the run: its sha256 is recorded at start and end,
and the run is void if they differ.

## Task sequence (per seed: 11, 22, 33)

- **Phase A**, 3 families. Relations `a b c d` (random names). 5 layers of 10
  random entities, and every relation is a random function from each layer to the next.
  Tasks per family:
  `t1=a+b`, `t2=a+b+c`, `t3=a+b+c+a`, `t4=b+b`, `t5=b+b+a+b`, `t6=d+a+b`.
- **Phase B** (distribution shift), 3 families. Relations `a…f`, 7 layers of
  8 entities, 15% of facts withheld (missing knowledge), and one entity per layer
  with a second value for one relation (ambiguity). Tasks:
  `t1=a+b`, `t2=a+b+c`, `t3=e+f`, `t4=e+f+a+b`, `t5=c+d`, `t6=c+d+a+b+c`.
  In the first phase-B family, `t2` first gets a wrong example (contradictory
  observation), then `correct example`.
- That gives 36 tasks. Programs are hidden from the learner. The teacher answers only questions.
- Per task: 2 examples on non-sealed layer-0 subjects with a single defined answer.
  Then, while the result is not `qualified`, up to 4 rounds of `investigate`.
  The teacher refuses (`unanswered`) any question about a sealed subject.
- **Sealed evaluation:** in each family, the layer-0 subjects with index ≥ 5 (phase A) or
  ≥ 4 (phase B) are never examples and never answered as questions. Transfer graphs
  are also sealed: new entities with the same relations, 6 per layer, taught
  after the family, then queried with every capability of the family.
- **Corrections:** at the end of each phase-A family, one fact on layer 1 is corrected.
  Every sealed query of the family is re-asked against the corrected truth.
- **Retention:** after each family, all earlier sealed queries are re-asked.
- Every engine call is a new process. An interaction is one interface line.

## Arms (same sequence)

| arm | description |
|---|---|
| C | continual: one state, library on, activation on, `--deepen=5` |
| B | empty-memory: fresh state per task, re-taught the family facts and corrections so far, `--no-library --deepen=5` |
| P | primitive-only: one state, `--no-library --deepen=5` |
| F | frozen: as C in phase A, then nothing is taught in phase B (evaluation only) |
| S | shuffled evidence: as C, but example and answer values are rotated across subjects |
| G | geometry-disabled: as C with `--no-geometry` |
| N | activation ablation: as C with `--no-activation` |
| R | symbolic reference: `reference.learn` per task from the family facts, max length 5, in process |

## Pre-registered thresholds (arm C, every seed)

1. Retention: at least 0.99 of earlier sealed answers unchanged at each recheck, excluding queries whose truth was changed by a correction.
2. Plasticity: at least 0.9 of tasks acquired, with the base program equal to the hidden one.
3. Transfer: accuracy of at least 0.95 on defined transfer queries.
4. Semantic accuracy: 0 wrong answers on sealed queries from `qualified` capabilities.
5. Correction propagation: every sealed query whose truth changed answers the new truth.
6. Uncertainty: 0 answers where the truth is undefined. At least 0.95 of queries with an ambiguous truth reply `ambiguous`.
7. At least 1000 interactions and at least 30 processes.
8. Controls: F acquires at most 0.1 of phase-B tasks; S matches at most 0.1 of tasks; G makes the same acquisitions as C.
9. Engine sha256 unchanged.

## Amortization (research measurement, pre-registered in the ledger at 20:45)

- `A_n = 1 − C_C(n)/C_B(n)`. Cumulative engine CPU over tasks 1..n covers load,
  validation, teaching, acquisition, investigation, evaluation and save.
  It is reported only while C and B have equal sealed accuracy on tasks 1..n.
- `A^reuse_n = 1 − C_C(n)/C_P(n)`: same rule against the primitive-only arm, P.
  This separates capability reuse from knowledge retention.
- H1: `A_36 > 0` against B in all seeds. H2: `A^reuse_36 > 0` against P in all seeds.
  Either result is reported as it falls.
- Secondary measures: candidate evaluations, bit-row operations, executions, state bytes,
  examples plus questions per task, and wall time.
