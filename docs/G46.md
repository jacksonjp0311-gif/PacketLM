# G46 — longitudinal continual learning (pre-registered)

Written and committed before `benchmarks/g46.py` produces any result.
The engine source is frozen for the run: its sha256 is recorded at start and end,
and the run is void if they differ.

## Task sequence (per seed: 11, 22, 33)

- **Phase A**, 3 families. Relations `a b c d` (random names). 5 layers of 10
  random entities, and every relation is a random function from each layer to the next.
  Tasks per family:
  `t1=a+b`, `t2=a+b+c`, `t3=a+b+c+a`, `t4=b+b`, `t5=b+b+a+b`, `t6=d+a+b`.
- **Phase B** (distribution shift), 3 families. Relations `a…f`, 7 layers of
  8 entities, 15% of facts withheld (missing knowledge), and one entity per layer
  with a second value for one relation (ambiguity). Tasks:
  `t1=a+b`, `t2=a+b+c`, `t3=e+f`, `t4=e+f+a+b`, `t5=c+d`, `t6=c+d+a+b+c`.
  In the first phase-B family, `t2` first gets a wrong example (contradictory
  observation), then `correct example`.
- That gives 36 tasks. Programs are hidden from the learner. The teacher answers only questions.
- Per task: 2 examples on non-sealed layer-0 subjects with a single defined answer.
  Then, while the result is not `qualified`, up to 4 rounds of `investigate`.
  The teacher refuses (`unanswered`) any question about a sealed subject.
- **Sealed evaluation:** in each family, the layer-0 subjects with index ≥ 5 (phase A) or
  ≥ 4 (phase B) are never examples and never answered as questions. Transfer graphs
  are also sealed: new entities with the same relations, 6 per layer, taught
  after the family, then queried with every capability of the family.
- **Corrections:** at the end of each phase-A family, one fact on layer 1 is corrected.
  Every sealed query of the family is re-asked against the corrected truth.
- **Retention:** after each family, all earlier sealed queries are re-asked.
- Every engine call is a new process. An interaction is one interface line.

## Arms (same sequence)

| arm | description |
|---|---|
| C | continual: one state, library on, activation on, `--deepen=5` |
| B | empty-memory: fresh state per task, re-taught the family facts and corrections so far, `--no-library --deepen=5` |
| P | primitive-only: one state, `--no-library --deepen=5` |
| F | frozen: as C in phase A, then nothing is taught in phase B (evaluation only) |
| S | shuffled evidence: as C, but example and answer values are rotated across subjects |
| G | geometry-disabled: as C with `--no-geometry` |
| N | activation ablation: as C with `--no-activation` |
| R | symbolic reference: `reference.learn` per task from the family facts, max length 5, in process |

## Pre-registered thresholds (arm C, every seed)

1. Retention: at least 0.99 of earlier sealed answers unchanged at each recheck, excluding queries whose truth was changed by a correction.
2. Plasticity: at least 0.9 of tasks acquired, with the base program equal to the hidden one.
3. Transfer: accuracy of at least 0.95 on defined transfer queries.
4. Semantic accuracy: 0 wrong answers on sealed queries from `qualified` capabilities.
5. Correction propagation: every sealed query whose truth changed answers the new truth.
6. Uncertainty: 0 answers where the truth is undefined. At least 0.95 of queries with an ambiguous truth reply `ambiguous`.
7. At least 1000 interactions and at least 30 processes.
8. Controls: F acquires at most 0.1 of phase-B tasks; S matches at most 0.1 of tasks; G makes the same acquisitions as C.
9. Engine sha256 unchanged.

## Amortization (research measurement, pre-registered in the ledger at 20:45)

- `A_n = 1 − C_C(n)/C_B(n)`. Cumulative engine CPU over tasks 1..n covers load,
  validation, teaching, acquisition, investigation, evaluation and save.
  It is reported only while C and B have equal sealed accuracy on tasks 1..n.
- `A^reuse_n = 1 − C_C(n)/C_P(n)`: same rule against the primitive-only arm, P.
  This separates capability reuse from knowledge retention.
- H1: `A_36 > 0` against B in all seeds. H2: `A^reuse_36 > 0` against P in all seeds.
  Either result is reported as it falls.
- Secondary measures: candidate evaluations, bit-row operations, executions, state bytes,
  examples plus questions per task, and wall time.

## Clarifications (committed with the harness, before any G46 result)

- **Acquired** means the current version's status is qualified or provisional and its
  expanded base equals the hidden program. S "matches" uses the same rule.
- **Investigation:** at most 4 `investigate` calls per task. A refused question
  counts toward the 4. The answer to one question and the next `investigate` share a process.
- **A sealed reply is correct when:** the truth has one value and the reply gives it; the truth is
  ambiguous and the reply starts with `ambiguous`; or the truth is undefined and the reply gives
  no value. Equal accuracy for `A_n` means that, for every task ≤ n, C and B have
  the same number of correct sealed replies.
- **Cost attribution:**
  - Task cost covers the task's own calls: the family facts on that family's first task
    (on every task for B), examples, investigation, and the task's sealed evaluation.
  - Corrections, transfer and retention calls are instrumentation and maintenance.
    They are reported separately.
  - `A_n` is reported twice: on task costs, and conservatively with all of C's
    extra calls charged to C.
- **R** receives the same examples and teacher answers that C received for the task.
- **Sealed tokens:** the harness writes the sealed subjects and transfer entities to
  `benchmarks/sealed_tokens.json`, which `teach.py` refuses. The receipt checks that
  none of them occurs in `data/trained/state.json`.
- **Example pool** (fixed after inspecting the generated world only, before any
  engine run): with 15% missing facts, four layer-0 subjects sometimes have no
  single-valued answer, so a task could not be taught. Examples are drawn from the
  non-sealed layer-0 subjects first, then from layer 1. Sealed subjects are unchanged.

## Amendment 1 (21:22 EST, after an aborted first attempt; no arm result was read)

The first registered attempt started at 21:12 EST and was stopped at 21:21 EST. Arm N
(`--no-activation`) was spending more than 300 s of wall time per engine call once phase B
began: its candidate search enumerates every program over all accumulated relations and
capabilities up to length 5. At that rate the arm would have needed many hours.

The harness only wrote results at the end, so nothing from the attempt was read or kept.

Changes:
- **Harness only** (the engine is unchanged, sha recorded):
  - each arm's result is written as it finishes (`result_<arm>.json`), so a run can resume;
  - arm N gets a per-call wall budget of 120 s. If a call exceeds it, the arm stops and
    its partial result is recorded as `aborted` with the place it stopped.
- **N's role:** N was never part of a threshold. It is a cost ablation, and an abort is
  reported as that ablation's result.
- **Unchanged:** every other arm, threshold and seed.

### Amortization (pre-registered H1, H2) and the learning-amortization instrument

**H1 is false.** The continual learner costs far more than the empty-memory learner.
- From C's own receipt, on the equal-accuracy prefix only (tasks 1..29, 1..23 and 1..21):
  `A_n` = −5.47, −5.45 and −4.90.
- Pinned instrument, all 36 tasks:
  - `A_36(C‖B)` = **−7.00 [−7.19, −6.85]** (paired bootstrap, S=3; sign-flip p = 0.25,
    the minimum possible with 3 seeds);
  - censoring: C 1 task, B 11. B's censoring makes this a lower bound, but that cannot change its sign;
  - no break-even;
  - the trend of the per-task log ratio is −0.069 per task: the gap widens.
- With maintenance charged (`C+maint`): −7.71.

**H2 holds on the instrument, but not on the receipt's equal-accuracy rule.**
- `A^reuse_36(C‖P)` = **+0.225 [+0.210, +0.254]**; break-even at task 28; censoring C 1, P 11.
- The receipt's strict equal-accuracy rule gives no value, because C acquired 4–5 more tasks
  than P. That makes P's cost a lower bound, so the true reuse saving is at least this large.

**Reading:**
- Capability reuse saves CPU against a learner that keeps the same memory without a library.
  The library also buys accuracy: C acquired 35–36 tasks, B and P 31–32.
- Keeping memory at all costs much more than it saves against relearning each task from empty
  memory. This is the utility problem, measured.
- None of this supports a learning-to-learn claim.

### Unexpected observations

1. **Where the cost goes.** Profile of one phase-B acquisition on C's final state:
   - 15.1 s for acquisition plus investigation, against 0.06 s to load and 0.09 s to save;
   - 93% of it is the open-world qualification scan from audit item 2 (`_scan`): 35,107 programs
     walked and 4,920 blockers found.
   The scan's cost grows with everything retained, not with what is relevant:
   - per-entity prediction tables and `_differs` run over all 534 entities;
   - library capabilities enlarge the scan;
   - P pays the entity cost without the library and is slowest of all.
   Correctness fix → cost: the P0 fix made qualification honest and made it expensive.
2. **Phase B is all provisional.** With missing and ambiguous facts, every C task in phase B
   stayed provisional after 4 investigations. Open-world blockers survive because the teacher
   refuses questions about sealed subjects and undefined answers. Answers were still 100%
   correct where given, but every one was marked `[provisional]`.
3. **Geometry costs more.** G (symbolic) made identical decisions to C at 58% of C's CPU.
   The bit-row path is slower than python sets at this scale, so no Bitwork speed advantage
   is shown (relevant to G48).
4. **The library supplies reach, not just speed.** In phase B, B and P ended `ambiguous` at depth
   ≤5 on tasks that C settled by composing two capabilities (efab, cdabc, abc). C's 4–5 extra
   acquisitions per seed are tasks the others could not resolve at all.
5. **Without activation pruning (N), phase-B acquisition exceeds 120 s per call.** That is the
   ablation result for the developer improvement of 20:50.
