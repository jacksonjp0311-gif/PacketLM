## 1. Why (the switch rule)

G59 (docs/G59.md §12) was HOLD and triggered James's switch rule (G58 §8, G59 §8): evaluate an
alternative mathematical approach with the same instrument and verification setup instead of
optimizing the engine further. G59's diagnosis: C needs ~8–9× fewer evaluations than B but each costs
13–30× more CPU (ρ 12.9 comp → 29.8 long), overhead grows ~2.1× faster than savings, and only the
deepest stratum reaches break-even. The verifier of G59 (verify-80cfb17, M1) adds that G59 did not show
the representation alone is the limit: losses split into state carriage without a library (P‖B),
library use (C‖P) and maintenance. G60H therefore pre-registers that decomposition (§6c) so the term
HDC changes can be identified. James chose the route (2026-11-27): fixed-width hyperdimensional /
vector-symbolic codes, kept in his sparse binary geometric spirit. This is a SMALL prototype; it stops
after its registered result.

## 2. Mechanism (`packetlm/hdc/`, new; the existing engine is not modified or imported)

- **Codes** (`codes.py`): sparse block codes, K = 32 blocks × L = 64 positions (D = 2048, exactly 32
  ones), stored as packed block indices. bind = blockwise addition mod L (invertible), ρ = block
  permutation, bundle = OR of one-hot vectors, cleanup = items whose code is fully contained in a
  bundle (candidates from two key blocks, verified on all K blocks). Every operation is O(K).
- **Fact memory**: heteroassociative, key = bind(code(s), ρ(code(r))) → value codes. A step (s, r) is
  one bind and one lookup, whatever else is stored.
- **Entity signature** S_e = OR of relation codes; **capability** H_c = OR_k ρ^k(code(step_k)) (a
  composed hypervector), applied by decoding position by position (cleanup over the primitive
  codebook) and executing the steps; the decode is checked against the exact journal copy (charged;
  a mismatch is counted as a decode error and the exact copy is used). **Capability index** F_r = OR of
  qualified capabilities whose first base relation is r. Offered primitives at an entity =
  decode(S_e) ∪ decode(F_r), r ∈ decode(S_e): local to the entity, not to the global library.
- **Search** (identical for every arm; `--no-library` only removes capabilities from the offered set):
  iterative deepening over primitive sequences as a dynamic program over tuples of entity sets on
  X = observed subjects + Ω (≤ 16 subjects of s1's relations in the order told); equal tuples are equal
  functions on X and are expanded once; a tuple empty at a value-observed subject is pruned.
  Supported = matches every observation (value, `!none`, `!several`). At the first depth n with
  support: several distinct tuples → `ambiguous` (investigate asks the X entity with the best
  worst-case split, ties by name); one → candidate, searched **margin** more levels; a new supported
  tuple there blocks (→ `provisional`), else `qualified`. Answers are qualified only on X; elsewhere
  `[provisional]`. Registered primary margin = 1 (the rule in the module docstring since 7f06658,
  before any result); margin = 2 is a registered robustness run (§6e).
- **Serve** (`serve.py`): the JSON protocol and CPU accounting of packetlm/serve.py (call / inspect /
  close; `cpu_total_s` = process CPU since the previous charged request); one fsync'd journal record
  per call; snapshot (JSON of the exact copy + full validation: signatures, fact keys and capability
  index rebuilt and compared) every 64 journaled calls and at path change/close; new path → empty
  snapshot first; gc.freeze after snapshots (as G59 §2d); per call a change-scoped check (every written
  key unbinds to its subject, values have clean codes, signature holds the relation). Journal replay on
  reopen must reproduce every recorded reply hash.

**Semantic difference from G59, stated up front.** G59's engine qualified a program only if no
alternative within a horizon of `deepen` (5) primitive steps blocked it, with byte-exact search state.
G60H's horizon is n + margin in each arm's own primitive language (same rule for every arm). This is a
weaker uniqueness certificate than G59's, and it differs between arms because their languages differ
(C's includes its library, so the library acts as a description-length prior). Safety is measured, not
assumed: wrong-qualified answers (sealed and transfer), retention and C ≥ B sealed correctness are
gate conditions (Q2), and accuracy-matching/censoring follow the instrument. Dev data (§7) show the
result depends strongly on margin; that dependence is part of the registered reading.

## 3. Exactness and accuracy (approximation is measured, not denied)

HDC operations are approximate in principle: bundle cleanup can return spurious items (all K blocks
collide, rate ≈ (d/L)^K per candidate), composed hypervectors fail when positions alias (m > K) or
bundles are dense, bound keys can collide (≈ M²/2L^K; a collision would merge two facts and the
registered engine does not detect it). `benchmarks/g60h_capacity.py` measures these over K ∈ {4, 8, 16,
32} × L ∈ {16, 64} (not timed). Dev (`g60h_capacity_dev`): misses 0 everywhere (OR bundles keep
members); at the registered K = 32, L = 64 spurious 0 for bundles up to d = 32 of a 20k codebook,
sequence decode errors 0 up to m = 8, key collisions 0 at 10^5 facts; the approximation regime starts
at small K: K = 8, L = 16: 13 spurious per bundle at d = 8 and 98% sequence errors at m = 8; K = 4:
key collisions 268–47,808 at 10^5. In-run decode errors (capability decodes vs the exact copy) are
counted and charged. Cleanup cost is O(d²·(1 + M/L²)) for a codebook of M items: at the registered
sizes M/L² ≪ 1, but it is a knowledge-dependent term (coefficient 1/L²), reported, not hidden.
