# G53: where the persistent learner's CPU goes, and an exact bound on library cost

Steering at 01:12 (America/New_York, 2026-11-27):
1. Diagnose the extra CPU of the persistent learner by phase, with evidence.
2. Pre-register a bounded library-cost mechanism grounded in that profile, without changing the
   soundness or thresholds of the qualified path.
3. Measure it with the same instrument, the same controls and new seeds, at least 7 per

### Findings

**F1. Compositional curriculum: the library's cost is the open-world qualification scan.**
- The library cuts the acquisition search: C's search time is 6.8, against P's 56.2.
- But it multiplies the scan: C's scan time is 220.0, against P's 90.2.
- Library capabilities are scan primitives, so the alternative space grows with the library.
- Per scan, most of the work was bookkeeping:
  - about 300k relevance-pruned (primitive, node) pairs, against about 25k scanned nodes;
  - fronts of size |D| re-stepped base relation by base relation for every node.

**F2. Re-acquisition triggered by `complete`.**
- `complete s` re-acquires every capability observed at s. In a family, earlier tasks share
  subjects, so most of these re-acquisitions are of already **qualified** versions.
- This is about 60% of C's teach time, counting the scans nested inside it.

**F3. Unrelated curriculum: the cost is mostly maintenance, and none of it is library search.**
*(Revised after verify-cdb4828 G2, which showed the first version did not separate maintenance
from library search.)*
- C equals P there (19.7 s against 19.5 s), and the library is used 0 times. Library search
  (`hypotheses`) is 0.3 s of C's 19.7 s.
- Split by call kind: C's teach calls take 6.2 s (B: 1.7 s); its evaluation calls take 13.4 s
  over 72 calls (B: 1.0 s over 24 calls). The 48 extra calls are the retention re-asks of earlier
  families, which the G51 cost charges as maintenance: about 68% of C's cost here (G51's
  registered figure is 65%, 48.4 of 74.8 s). Without maintenance, G51 gives A(C ‖ B) = −1.15
  [−1.18, −1.12], a 2.15× ratio.
- What remains is state-proportional, per process call: load, validation and save of the whole
  state (8.6 s), and the geometric `ask`, which scores every stored fact's packet per question
  (10.9 s, nested in evaluation). Per evaluation call C costs 0.19 s against B's 0.04 s.
- A library mechanism cannot address this. It is the process-per-call architecture and the
  retrieval cost.

## 2. Mechanism: `--bounded` (exact; same decisions, same replies)

**Four changes,** none of which changes a decision:

1. **Memoized primitive images in the scan.**
   - The image of a set under a primitive is the union of the images of its nodes. This holds
     for relation steps, and for until steps, which act node by node.
   - So the (primitive, node) images are cached for the whole scan.
2. **Primitives indexed by first base relation.**
   - A scan node visits only the primitives whose first relation leaves its frontier, in the
     original primitive order.
   - The skipped primitives are exactly those the existing relevance rule pruned: their image
     is empty whatever the path.
   - The `pruned_compatible` count is then kept for visited nodes only. This is marked in the
     scan record.
3. **Sparse fronts.**
   - A front is a map from domain index to a non-empty set; a missing index means the empty set.
   - Judgment, support and conflict are computed on it exactly as on the dense list.
4. **No re-scan of settled versions after a new `complete`** (base engine only).
   - A closed judgment differs from the open one only by turning *undetermined* into
     *contradicted* when the output is not None.
   - So it can only shrink the supported set and the set of non-contradicted alternatives. The
     marks of the alternatives that survive are unchanged.
   - Take a version that is qualified, still supported, and has the same **basis**. The basis
     is a digest of the fact epoch (any told or derived fact added or removed), the offered
     primitives, the observations, the horizon and the library flag.
   - Re-acquiring such a version cannot change its candidate, its status or its blockers, so it
     is skipped.
   - A retraction always follows a told-fact change, which changes the basis, so it is never
     skipped.
   - Programs mode is excluded, because there `complete` also changes the guard space (H1 rule).

**What is not changed:**
- the hypothesis space;
- the horizon;
- the blocker rule;
- the qualification rule;
- investigate.

**Tests:**
- Checks:
  - `g53_bounded_scan_equals_unbounded`: equal scan outputs and statuses, with a library and
    with blockers;
  - `g53_fc_skip_only_settled`.
- Mutations: `g53_memo_key_ignores_primitive`, `g53_index_drops_primitives`,
  `g53_sparse_conflict_ignored` and `g53_skip_ignores_basis`.
- A fifth mutation, which skipped even after a retraction, was an equivalent mutant: a
  retraction always changes the basis. The redundant guard it targeted was removed.

**Harness exactness guard:**
- Every Cb reply stream must hash-equal C's, call by call, on every seed.
- The dev run held on all 4 dev seeds.

## 2b. Soundness fixes from verify-cdb4828, in every arm

These change qualification semantics, so they are in the engine for **all** arms (C, Cb, Bb, Pb,
Fb). They are not part of the bounded mechanism, and the exactness guard (Cb equals C) still
applies. The dev run in §4 was redone with them.

- **S1 (High): re-scan on growth inside a region.**
  - A qualified version's scan was decided on the facts of its region: the component of its
    recorded domain and its observed subjects.
  - When a told fact is added or removed whose subject was already a known entity in that
    region, the version is re-acquired, which re-runs the scan on current facts.
  - A fact whose subject is a new entity cannot change any value at a previously known entity
    (a program reads outgoing edges only). Answers at new entities stay scoped as provisional
    (M2 of b2bb9b8) until `requalify`.
  - The work is batched: pending growth is handled before the next line that is not a `fact`
    line, and before saving.
  - Check: `s1_growth_in_region_requalifies` (the verifier's repro, plus a fact at a new entity
    that must not trigger). Mutations: `s1_growth_ignored`, `s1_region_is_domain_only`.
- **L1 (Low): qualified only on qualified dependencies.** A version that pins a `cap:` dependency
  that is not qualified is capped at provisional. A dependency going from qualified to
  provisional demotes its qualified dependents. Check: `l1_qualified_needs_qualified_deps`.
  Mutations: `l1_dependency_status_ignored`, `l1_no_demotion_propagation`.
- **L2 (Low):** `h1_identity_expressible_under_complete` asserts the positive case.
- **Consequence for G45 t5 (retention), restated.** Under S1, a later G45 domain built on an
  earlier domain's world demotes that earlier capability to provisional on all three seeds (a
  real alternative appears, for example `rel:zrdhxg>rel:kkabje` on seed 101). The strict
  "identical replies" reading now fails, so t5 is restated: every re-asked value is identical,
  and every changed reply is the same value marked provisional, of a capability re-scanned to
  provisional with blockers. The strict result is kept in the receipt
  (`retention_strict_identical`: false on 101, 202 and 303).

**Decision rules (fixed now):**

| rule | what is claimed, and when |
|---|---|
| **M (mechanism)** | A saving is claimed on a curriculum only if the lower bound of A(Cb+maint ‖ C+maint) is > 0 |
| **L1** | Learning-to-learn on the compositional curriculum is claimed only if the lower bound of A(Cb+maint ‖ Bb) is > 0 |
| **L2** | Reuse is claimed only if the lower bound of A(Cb+maint ‖ Pb+maint) is > 0 |
| **L3** | On the unrelated curriculum, if the upper bound of A(Cb+maint ‖ Bb) is < 0, the utility problem persists |

**Guards (run validity):**
- `exact_Cb_replies_equal_C` on every seed;
- 0 wrong-qualified sealed answers in C and Cb;
- the instrument is pinned and unmodified;
- every report ran;
- source unchanged.

If the exactness guard fails, the mechanism is not exact. The run is then reported as invalid
for M, and nothing is claimed.

## 4. Dev run (seeds 951–954; not evidence)

- **Run:** `python3 benchmarks/g53.py --dev --comp-seeds 951,952 --unrel-seeds 953,954`, redone
  after the §2b fixes (receipt `docs/evidence/g53/g53_dev_receipt.json`; the run before them is
  kept as `g53_dev_receipt_pre_S1.json`). A_n = 1 − C_cont/C_base, so the cost ratio is 1 − A.
- **Guards:** all held, including exact reply streams on all 4 seeds.

**Compositional curriculum:**
- Whole CPU (s): C 62.9, Cb 30.9, Bb 15.4, Pb 26.1, Fb 9.7.
- A(Cb+maint ‖ C+maint) = +0.509 [+0.499, +0.519] (Cb costs 0.49 of C).
- A(Cb+maint ‖ Bb) = −1.006 [−1.043, −0.968], a 2.01× cost ratio, against −2.87 (3.87×) for
  G51's C. *(An earlier draft read A as a log ratio; the instrument defines A_n = 1 −
  C_cont/C_base, verify-cdb4828 G1.)*
- A(Cb+maint ‖ Pb+maint) = −0.182; A(Cb ‖ Pb) = −0.221; A(Cb+maint ‖ Fb+maint) = −2.195.

**Unrelated curriculum:**
- Whole CPU (s): C 23.9, Cb 23.6, Pb 23.5, Bb 3.9.
- A(Cb+maint ‖ Bb) = −5.070 (6.07×).
- A(Cb+maint ‖ C+maint) = +0.012 [−0.004, +0.028], within CPU noise.

**Prediction:**
- M holds on the compositional curriculum. On the unrelated one the effect is near zero, so it
  may or may not clear 0.
- L1 and L2 fail: the gap narrows but stays negative.
- L3 holds.

The residual compositional gap is the qualification scan over library-extended alternatives.
That cost is semantic: the open-world space really is larger with a library. The unrelated gap
is mostly maintenance (retention re-asks), each paying state-proportional load, save and
retrieval (F3); none of it is library search.

**What this shows.** The library cost diagnosed in §1 was mostly removable bookkeeping: memoized
images, an index, sparse fronts and skipping settled re-scans halve C without changing any
reply. What remains on the compositional curriculum (Cb 99.3 s against Pb 85.6 s and Bb 52.7 s)
is the open-world scan over a larger, library-extended alternative space and per-call state
cost. Learning-to-learn on whole-process CPU is still not shown. The next lever is not the
library but the state-proportional per-call cost (load, validation, save, `ask`) and the
maintenance re-asks, which dominate the unrelated curriculum.
