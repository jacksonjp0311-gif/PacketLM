# G46 / G46-U / G47 re-measurement on engine v4 (pre-registered before the runs)

Engine: commit 6d29b75, `source_hash` 205d0829533f…. The engine is frozen for these runs.

## What changed from v3 (exact; no decision changes intended)

- **Schema 3.** Per-fact packets are no longer stored. They are derived by `bind` when a
  geometric ask needs them.
  - Packets were 85% of state bytes: 1024 hex characters per fact.
  - A schema-2 state is still accepted. Its stored packets are all checked, then the state is
    migrated explicitly; the migration is reported in the load report, and the v2 file becomes
    the backup. Nothing is reconstructed silently.
- **Save** no longer re-validates bytes this process already validated or wrote. It still
  validates its own state, and still validates any primary it did not read itself before
  backing that primary up.
- `bits_for` is memoized (a pure function).
- **Checks:** g44 77/77; suite 164/164; 33/33 mutations killed, with new ones for migration,
  packet roles, primary trust and the retention mechanism. G45 decisions are identical to
  v3: 18/18, same per-domain records.
- **G45 effect** (bytes and CPU per domain run): state 931 KB → 141 KB, engine CPU
  1.30 s → 0.23 s.
- Also present but off: `--operators` and `--adaptive-retention`. Neither flag is passed in
  these runs; adaptive retention is tested separately in docs/ARET.md.

## Protocol

Same harnesses, seeds, arms, budgets and thresholds as v3 (docs/G46.md with amendment 1,
docs/G46U.md, docs/G47.md). Nothing is re-tuned. The registered G46 result is unchanged
(v2: 26/27, not passed); v4 is reported beside it.

**Predictions:**
- Decisions are identical to v3 in every arm and seed (same acquisitions, sealed correctness,
  question counts).
- Task CPU falls in every engine arm.
- `A_36(C‖B)` stays negative. Retained knowledge is still carried, but it costs less per byte.

The learning-amortization instrument (pinned 70297af, unmodified) is run on the exported
costs as before.

## Results (engine 205d0829…; evidence in docs/evidence/v4/)

**The prediction held:** decisions are identical to v3 in every arm and seed for G46, G47 and
G46-U. That covers acquisitions, sealed correctness, examples plus questions, interactions,
processes, evaluations, metrics and thresholds. G46 seed 33 threshold 6 still fails, so
**G46 stays NOT passed (26/27)**. No timing outliers were found (no task > 5× its arm median).

**G47:**
- **H3** stays true.
- **H5** stays true, by a small margin: L's CPU per acquired task is 0.163 / 0.163 / 0.175 s
  against M's 0.175 / 0.177 / 0.176 s. In seed 33 the gap is 0.001 s.

**Reading:**
- `A(C‖B)` is still negative, so the utility problem remains.
- On the unrelated curriculum it is still large: the continual state costs about 10× an empty
  state per task.
- `A(K‖Q)` and `A(L‖M)` are more negative than in v3. The empty-library arms got
  proportionally cheaper, while the library arms still carry their state. The primitive arms
  are censored on 61 and 36 tasks, so these are lower bounds.
- docs/ARET.md tests whether the remaining size-driven cost can be removed by deciding what to
  keep hot.
