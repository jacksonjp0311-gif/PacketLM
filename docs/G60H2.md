# G60H2: the equal-check rule — C certified by B's base-language criterion, fully charged

Pre-registered 2026-11-27, before any registered G60H2 run. Branch `g60h2-equal-check` (from `g60h-hdc`
@ 69b5b26). Follows verify-69b5b26 (fe7f986): G60H's positive result used a library-relative uniqueness
check (+1 primitive in each arm's own language), so C's certificate was weaker than B's (H1); with B's
certificate imposed the verifier's counterfactual gave library term ≈ 0 and HOLD. G60H's corrected claim

## 1. Question

With the **same certificate for every arm** — B's (G59's) depth-relative uniqueness rule in base
primitives at the pre-registered margin, computed on the same evidence and fully charged — does the
learner C still amortize (gate Q1–Q4 of G60H, thresholds unchanged)? The library may only **propose**
candidates; it cannot weaken the check.

## 2. Mechanism (`packetlm/hdc/engine.py`, flags of `packetlm/hdc/serve.py`)

- **Equal check (`--check=equal`, C).** C's library search proposes: iterative deepening in C's language
  (relations + local qualified capabilities) up to its first supported depth (charged). Then the
  **base-language certificate** runs on the same evidence (charged): n = first base length with a
  supported tuple on X; several distinct supported tuples at n → `ambiguous`; one → candidate; any other
  supported tuple of base length ≤ min(deepen, n+margin) → `provisional`; else `qualified`. C's status,
  live set (hence its next question) and candidate tuple are exactly B's on that evidence. If the proposal
  is one tuple equal to the certified one, C keeps the library's (compositional) form of the program (the
  same function on X); otherwise it adopts the certified base program. Counters: `prop_agree`,
  `prop_differ`, `prop_none`, `cert_runs`.
- **Cheap certificate: meet in the middle (`--certifier=mitm`, every arm).** Forward images of all base
  prefixes of length ≤ 3 from the observed subjects (pruned when a value-observed subject has no image),
  inverse steps (an inverse fact memory, key bind(code(o), ρ²(code(r))) → subjects, and in-relation
  bundles) from the first observed value for suffixes of length deepen − 3, joined on the meeting entity;
  every joined program is checked exactly on all observations; distinct supported tuples on X are
  grouped by minimal length with the lexicographically first program as representative. This returns
  exactly the DP's verdict, tuples and representatives (proof sketch in the code docstring; unit test on
  random 6-layer and cyclic worlds; dev differential: byte-identical reply streams `--certifier=dp` vs
  `mitm` for every arm on all six curricula). Cost on dev ≈ 0.55–0.75 of the DP's. **All arms use it**
  (B and P too), so no arm gains from the algorithm alone; B with `--certifier=dp` is byte-identical to
  G60H's B.
- **Caching.** A per-engine image memo (entity, base prefix) → set, cleared whenever a known entity gets
  a new fact or a correction (exact). It persists across calls, so long-lived arms (C and P alike) reuse
  it within a family: it is state carriage, not library, and shows in P‖B. No library-specific certificate
  cache is registered: the certificate is a function of the evidence and the facts only (not of which
  candidate is proposed), so a proposal-only library cannot make it cheaper, and the predicted library
  term under the equal check is ≤ 0 (proposal cost). This is the structural prediction tested here.
- **G60H rule kept** as `--check=own` (default, byte-identical to G60H's C on dev) for the decoy contrast.

## 3. Counters (verifier L1, L3)

Every hypervector read now has a counted exact check: bound-key collisions (owner (s, r) stored per key;
colliding pairs kept in an exact spill table; `collisions`, `inv_collisions`, `key_collision_reads`);
code collisions (`code_collisions`; reads touching a shared code use the exact journal copy,
`code_collision_reads`); signature and in-signature decodes (`sig_spurious/missing`,
`isig_spurious/missing`; exact sets used); capability-index decodes (`capidx_spurious/missing`);
capability decodes (`decodes`, `decode_errors`, as G60H). The harness records every arm run's cumulative
counters in its job record and the receipt (`hdc_counters`, summed per arm). Test: with K=2, L=4 every
collision kind occurs, is counted, and answers equal the plain engine's.

**Reading (claim of record).** With the same base-language certificate for every arm (B's rule at +1,
computed by an exact meet-in-the-middle search and fully charged), C does not amortize: comp
A(C+maint‖B) −0.022 [−0.047, +0.006]; HOLD at +1 and +2. The library term is negative (comp −0.41
[−0.46, −0.36]): an exact certificate defined by the evidence and facts alone gives the same verdict and
the same questions whatever is proposed, so a proposal-only library can add only its proposal cost. The
remaining saving of long-lived arms is state carriage (P‖B +0.37 on comp), available without a library.
The hypervector representation costs CPU with identical answers (A(HDC‖plain) comp −0.49 [−0.52, −0.46]),
so G60H's engine gains are not due to the representation. The equal check holds the decoy at 0
wrong-qualified answers, where G60H's own-language rule gives 68. Positive amortization from a library
under an equal certificate remains open; it would need reuse of certificate work itself (a pre-registered
change of what is certified), not a better proposer.
