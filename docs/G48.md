# G48: acquiring type-constrained, variable-depth and conditional programs (pre-registered)

This was written and committed before `benchmarks/g48.py` ran on any registered seed. The
dev runs (seeds 998 and 999) and the changes they led to are committed with this file, in
`docs/evidence/g48/dev/`, so the development history is public (verification L1).

## What is designed and what is acquired

### Designed (`packetlm/programs.py`, stated precisely)

**Grammar**

| element | form |
|---|---|
| token | `rel:R` (set image along R), `cap:N@v` (an executable library capability), `is:Q:T` (keep x with the fact `x Q T`), `not:Q:T` (keep x without it), `self` (tail recursion: the whole program applied to every current node, at depth ≤ 8) |
| clause | 1–3 tokens |
| program | 1 clause containing a step, or 2 clauses where the first contains a guard and the second contains a step **or ends in `self`** (a recursive second clause need not contain a step; corrected after verification L6 of 82dd0a2) |
| `self` | only as the last token of the last clause |
| size | the number of tokens, at most 5 |
| ordered choice | the clauses are tried in order on `{x}`; the first non-empty result is the answer set |

**Proposals**
- **Guards:** the (Q, T) pairs shared by every observed answer, then the (Q, T) pairs of
  observed subjects that hold for at least 2 entities. At most 8.
- **Relevance:** the vocabulary is the relations and the executable capabilities whose
  subjects or observations lie in the connected component of the observed subjects and
  answers, connected through told facts. That component is also the domain for ambiguity and
  for the open-world scan. This narrows the engine's open world, which covers every relation,
  to the component the observations live in, and is a stated assumption.

**Selection**
- The search takes the smallest size that has a program supporting every observation.
- If supported programs that predict differently anywhere in the domain remain, the result is
  **ambiguous**. One representative of each prediction class is kept.
- Otherwise the result is the canonical first program.

**Open-world status**
- Every non-contradicted program up to the candidate's size is an alternative. The text
  originally said this horizon "is the same as the engine's deepening". **That was wrong**
  (verification N2 of 82dd0a2): the base engine scans to its full deepening budget (audit
  283f526 P0), and this candidate-size horizon is the short horizon that audit removed. From
  G48R2 on, programs mode scans to MAX_SIZE.
- An alternative blocks if it conflicts with the candidate, or if it has support and differs
  from it anywhere.
- The result is **qualified** only if the enumeration completes within 200,000 programs with no
  blocker. Otherwise it is **provisional**.

**Investigate (programs mode only)**
- An answer v removes every hypothesis that does not predict v, including those that predict
  nothing there, because a supported program has to support every observation.
- The engine asks the entity with the best worst-case elimination.
- This applies the seed-33 mechanism (docs/G46_SEED33.md), where the base engine only scored
  splits on which both hypotheses are defined. It came from dev seed 998, where all examples
  shared one answer and a guard on that answer's own property was indistinguishable.
- The base engine (G44–G47 behaviour) is unchanged.

### Acquired from observations
- which steps, guards and clauses are used;
- whether there is recursion, and so traversal to variable depth (until-like behaviour). Recursion is bounded by MAX_DEPTH = 8, so T1 programs answer up to depth 9 and give nothing from depth 10 on. The tested maximum is 7. (Earlier text said "any depth"; corrected after verification L1 of 82dd0a2.)
- conditionals (guard-first ordered choice);
- type filters;
- composition with library capabilities.

The old hand-designed `op:until` operator is not part of the grammar. Until-like behaviour is
a program the engine has to find, e.g. `rel:U>is:K:T|rel:U>self` or its reflexive variant
`is:K:T|rel:U>self`.

**What this does not claim:** the grammar itself (ordered choice, guards and tail recursion)
is supplied, just as sequential composition was. What is shown is that the engine selects
these structures from observations, not that it invented them.

## Protocol (`benchmarks/g48.py`)

**Setup**
- Seeds: 481–487 (S = 7, per verification M3).
- Each seed runs 2 rounds in one persistent state per arm. Every engine call is a new process.
- All names are fresh random tokens, relations included, in every world. Worlds are disjoint,
  so all graphs are unfamiliar.

**T1, until with variable depth**
- The world has 3 roots of a target type, each with a parent of another type, and chains of
  depth 1–5 below each root.
- Nodes are typed mid1/mid2, and the leaf of each chain has a leaf type. A distractor relation
  is present.
- Hidden program: `rel:U>is:K:tgt|rel:U>self`.
- Examples: one node at depth 1, one at depth 2, and one more at depth 1 or 2.
- Sealed items: every node at depth ≥ 3.
- Afterwards, new chains of depth 6 and 7 are taught and queried (transfer).

**T4, composition**
- In the same world: hidden `cap:<T1>` followed by `rel:C`, where C is each root's
  "capital".
- Examples at depths 1 and 2. Sealed items: depth ≥ 3, including the transfer chains.

**T2, conditional**
- 12 entities of class A or B, each with an R1 object and an R2 object.
- Hidden: `is:K:A>rel:R1|rel:R2`.
- Examples: 2 of class A and 2 of class B. Sealed: the other 8, plus 4 new entities afterwards.

**T3, type filter**
- 9 entities, each with 3 R-objects, exactly one of type T.
- Hidden: `rel:R>is:K:T`.
- Examples: 3. Sealed: the other 6, plus 3 new entities afterwards.

**Teaching**
- Facts, then the examples, then at most 4 `investigate` rounds answered by the harness.
- The harness refuses questions about sealed items and items with no single value
  (`unanswered`).
- Truth comes from an independent interpreter, `programs.run_naive`, over the harness's own
  triples.

**Arms**
- **P:** `--programs`.
- **X:** sequences only, using the base engine with `--deepen=3` (control).
- **S:** `--programs` with every taught answer replaced by another valid answer of the world
  (shuffled control).
- **A:** `--programs --adaptive-retention` (G48 with adaptive retention on).

**Metrics**
- Accuracy = correct / all sealed and transfer items with a defined truth. An unanswered item
  counts as wrong, so coverage is included.
- Cost: whole-process CPU (`cpu_total_s`, startup included), summed over every call.

## Thresholds (all must hold; P pooled over the 7 seeds)

- **H1.** P accuracy ≥ 0.95 in each class: T1, T2, T3 and T4.
- **H2.** P accuracy ≥ 0.95 on T1 items at depth ≥ 3 (depths never shown), including depths 6–7.
- **H3.** P gives 0 wrong qualified answers. The number of qualified tasks and of qualified
  answers is reported, so it is visible whether this check has anything to bite on.
- **H4.** X accuracy ≤ 0.5 on T1–T3.
- **H5.** S accuracy ≤ 0.10 overall.
- **H6.** A's replies are byte-identical to P's for every seed (no harm from retention). A's
  cost is reported against P, descriptively.
- **Source unchanged** during the run.

The status mix (qualified or provisional) and the acquired programs are reported per task.
Provisional is expected for T1, T2 and T4: an alternative that is undefined where the
candidate is defined cannot be excluded by an answer when the teacher refuses sealed items.

## Dev runs (seeds 998, 999, not registered)

1. **Dev 1:** the T1 examples were sampled from depths ≤ 2 without stratification. On seed 999
   round 2 all of them were at depth 1, and `rel:U` was acquired. The fix: one example at each
   depth, as OPS-1 did.
2. **Dev 2:** on seed 998, all 3 examples had the same answer, and a guard on that answer's own
   property (its capital) was supported. Investigate could not ask, because the split was
   one-sided. The fix is the programs-mode investigate above (mechanism, not tuning).
3. **Dev 3, after both fixes:** every threshold held on seeds 998 and 999.
   - P: T1 1.0 (n 124), T2 1.0 (48), T3 1.0 (36), T4 1.0 (124); depth ≥ 3: 1.0.
   - Wrong-qualified 0; qualified tasks 4.
   - X: 0.0. S: 0.0.
   - A was identical to P.
   - Receipt: `docs/evidence/g48/dev/g48_dev_receipt.json`.

## Results

**Registered run:** pre-registration commit 8fa5c7b. The engine sha256 is in
`docs/evidence/g48/g48_receipt.json`, with the raw data in `g48_raw.json`. Seeds 481–487,
S = 7; 56 tasks per arm.

**Verdict: 6 of 7 checks pass; H6 FAILS, so G48 is NOT passed as registered.**

| threshold | result |
|---|---|
| H1: P per class ≥ 0.95 | **pass**: T1 1.000 (n 434), T2 1.000 (168), T3 1.000 (126), T4 1.000 (434) |
| H2: P T1 depth ≥ 3 ≥ 0.95 | **pass**: 1.000 (n 378). Depths 6–7 transfer: 1.000 (n 42). |
| H3: P wrong-qualified = 0 | **pass**: 0, over 14 qualified tasks (all T3) and 126 qualified answers. **Restated after verification N2:** all 14 were qualified only because of the short candidate-size horizon. At horizon 3 every one has 4–5 blockers (e.g. `is:K:T\|rel:R>is:K:T`), so under the engine's full-horizon rule all 14 would be provisional and H3 would have nothing to test. |
| H4: X T1–T3 ≤ 0.5 | **pass**: 0.000 (n 728). X overall is 0.024, from T4 accidental paths. |
| H5: S overall ≤ 0.10 | **pass**: 0.0009 (1/1162) |
| H6: A replies identical to P | **FAIL**: seeds 481 and 487 differ |
| source unchanged | pass |

**What P acquired**
- T1: in all 14 tasks, a recursive two-clause program (guard first, then `self`). Every one was
  provisional.
- T2: in all 14 tasks, a guard-first conditional. All were provisional.
- T3: in all 14 tasks, the filter `rel:R>is:K:T`, **qualified** each time (the scan completed
  with no blocker).
- T4: in all 14 tasks, `cap:<T1>@v>rel:C`, using the library. All were provisional.
- P asked 168 questions in total.
- No program was supplied, and the old `until` operator was off.

**H6 failure mechanism.** I diagnosed it from the raw data and did not tune it away.
- The difference is only in round 2's T4 on seeds 481 and 487: `investigate` chose different
  question subjects. The acquired programs, statuses and every sealed or transfer answer are
  identical; accuracy for A is 1.000 on all 1162 items.
- Cause: investigate breaks ties by iterating the entity index, which follows fact storage
  order. Adaptive retention restores an archived component by appending its facts, so the
  order changes and a different tied entity is asked first.
- This differs from ARET's H-R1, which compared task rows and family records. G48's H6 compared
  every reply byte for byte, so it is stricter, and it caught this.
- **Correction (verification N1 of 82dd0a2): this diagnosis was incomplete.** Sorting fixed the
  order but not the candidate *set*. Investigate scored every hot entity, and retention removes
  archived worlds from the hot index, so P and A chose from different sets. The diagnosis was
  confirmed on G48R and fixed by restricting investigate to the observations' component (see
  G48R.md); a set-equality check under retention now tests it.
- **Fix, after the run:** in programs mode, investigate iterates entities sorted by name.
  - New check: `programs.prog_question_independent_of_fact_order`.
  - New mutation: `prog_order_dependent_ties`, killed.
  - The base engine keeps its order so that the G44–G47 results stay comparable. The same
    latent hazard exists there and is recorded in the ledger.
  - The registered result stays **FAIL**. Showing H6 under the fix needs a new pre-registered
    run.

**Leakage.** 0 of the 1214 G48 item tokens and G46 seed-44/55 sealed tokens occur under
`data/`.

**Correction (verification N3 of 82dd0a2):** in 6 of the 14 T4 tasks, one teaching example was
also a sealed evaluated item (6 of 434 T4 items). The T4 examples were drawn after the transfer
chains had been added to the pool. P is 1.000 either way, so H1 is unaffected. From G48R2 on, the
draw excludes sealed items, and the harness checks that no example is an evaluated item
(`no_example_is_evaluated`).

**Reading.** The engine selects recursion, guards and ordered choice from observations and
generalizes to depths it never saw (3–7), on graphs whose every name is new. Every case is
provisional except the type filter. Under the open-world rule and a teacher that refuses
sealed items, a less-defined alternative cannot be excluded by an answer. The grammar is
designed, as stated above.
