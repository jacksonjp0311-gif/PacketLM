## 1. Problem (from G52)

- Under `complete`, sound qualification in programs mode needs the guard space to be every (Q, T)
  pair on the acquisition component plus one absent pair (H1 of b2bb9b8). If that exceeds
  MAX_GUARDS = 8, qualification is capped at provisional (`scan.guard_gap`).
- In G52 the F arm's components carried 25–69 pairs (median 38.5), so F qualified **0/56** tasks
  (FC2 failed, as predicted).

## 2. Mechanism: `--closed-guards=N`

- Under a `complete` observation the full component pair space is used whenever it has at most N
  pairs; above N the cap applies as before. N is a constant: it does not depend on the
  observations, so the H1 soundness argument is unchanged. N = 8 (the default) is the G52 rule.
- A larger space is scanned by the same exact scan (`programs.Exact`, EXACT_BUDGET combinations).
  If the scan does not complete, the status stays provisional, as before.
- **Tests:** check `g55_budget_covers_component` (the H1 gap world: with N = 16 the gap is 0 and
  the status follows the completed scan). Mutation `g55_budget_ignored`.
  - *Corrected (verify-3e2783c Low 4):* the earlier text said the scan "finds a blocker, so it is
    provisional". That was wrong. There the completed scan finds **0 blockers** and `hq` is
    **qualified** (gap 0, domain {a, c}); `what is d hq` is answered provisional through M2.
