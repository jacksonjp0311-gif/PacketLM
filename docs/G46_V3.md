# G46 / G46-U / G47 re-measurement on engine v3 (pre-registered before the runs)

## Engine changes (exact developer improvements; none changes a decision)

- Qualification scan:
  - breadth-first over distinct base sequences;
  - stops at 64 blockers, after which counts are lower bounds and `truncated` is set;
  - restricted by a relevance index (only primitives whose first relation leaves the frontier).
- Predictions and differences are computed only where a program can be defined.
- `geom.compose` and `geom.bits` iterate set bits only.

Checks: suite 151/151, `audit.scan_matches_bruteforce`, `audit.compose_matches_naive`,
24/24 mutations killed, and G45 decisions identical.

Also present but off: operators (`--operators` is not passed in any of these runs).

## Purpose

The v2 runs found the utility problem: `A_36(C‖B)` = −7.0 and `A_24(C‖B)` = −23.1. This
re-measurement asks how much of it was implementation cost rather than retained-knowledge cost.

## Protocol

Same harnesses, seeds, arms, budgets and thresholds as docs/G46.md (with amendment 1),
docs/G46U.md and docs/G47.md. Nothing is re-tuned.

- The v2 results stay as the registered G46 result: 26/27, not passed.
- The v3 results are reported beside them and do not replace them.
- Prediction: decisions differ from v2 only through investigation order, because the blocker
  list order changed. Thresholds should be about the same.
- `A(C‖B)` will still be negative, since C still carries all retained knowledge into every call.
- Open question, answered as it falls: whether `A(C‖B)` crosses 0 anywhere on the
  compositional curriculum.
