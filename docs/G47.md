# G47: hierarchical reuse under matched budgets (pre-registered)

Written before any G46 or G47 result was read. Same world generator, seeds (11, 22, 33),
teacher, sealed evaluation, corrections and retention as G46 (`benchmarks/g46.py`), on the
same frozen engine.

## Arms (same question budget, 4 investigations per task)

| arm | library | depth budget |
|---|---|---|
| K | on  | 2 |
| Q | off | 2 |
| L | on  | 3 |
| M | off | 3 |

From G46: C (library, depth 5) and P (no library, depth 5).

## Measures

- tasks acquired, by shape;
- sealed accuracy;
- wrong qualified answers;
- task CPU;
- candidate evaluations;
- bit-row operations;
- executions;
- maintenance CPU (correction, transfer and retention calls);
- questions asked;
- final state bytes;
- library uses.

**Cached results vs capabilities:** G46/G47 never call `derive`, so no conclusion is cached
as a fact. Every answer is computed by running a stored program, and the receipt counts
`cap:` facts to confirm this.

## Hypotheses (reported as they fall)

- **H3 (reach):** at depth 2, K acquires at least 1.5× as many tasks as Q in every seed.
  Expected from structure: 7 of the 12 task shapes need base length ≥ 3. This tests that
  reuse provides the reach, not that it is surprising.
- **H4 (cost at equal reach):** at depth 5, where both can reach every task, C costs less
  CPU per task than P (`A^reuse_36 > 0` in G46).
- **H5 (budget efficiency):** at depth 3, L's CPU per acquired task is lower than M's.
- **No-harm condition:** K and L give 0 wrong qualified answers.
  A library must not trade correctness for reach.

Maintenance overhead of the library (more programs to requalify and scan) is reported
as maintenance CPU and state bytes. It is not hidden in task cost.

## Results (same frozen engine `cab85669629f…`, unchanged; run 21:34–21:40 EST)

Evidence in `docs/evidence/g47/`: receipt, raw data, LA CSV and instrument report.

| arm | acquired (s11/s22/s33) | wrong qualified | task CPU s | maintenance CPU s | questions | library uses |
|---|---|---|---|---|---|---|
| K lib d2 | 36/36/35 | 0 | 29.4/27.7/29.2 | 8.4/8.2/8.5 | 65/62/66 | 21/21/20 |
| Q prim d2 | 15/15/15 | 0 | 17.1/15.4/16.5 | 8.7/8.3/8.2 | 30/21/23 | 0 |
| L lib d3 | 36/36/35 | 0 | 52.5/53.3/51.3 | 8.7/8.5/8.5 | 77/81/78 | 21/21/20 |
| M prim d3 | 23/23/24 | 0 | 29.1/28.8/28.3 | 8.3/8.1/8.5 | 48/55/51 | 0 |

- **H3 (reach) true in all seeds.** At depth 2 the library arm acquires 35–36 tasks,
  primitive-only 15. Every task needing base length ≥3 is reached only by composition.
- **H4 true on the instrument.** From G46, `A^reuse_36(C‖P)` = +0.225 [+0.210, +0.254].
- **H5 false.** At depth 3, CPU per acquired task is 1.46–1.48 s (L) against 1.18–1.27 s (M).
  - M's cost is spread over fewer, cheaper successes. It is censored on 36 tasks.
  - Pinned instrument: `A_36(L‖M)` = −0.82 and `A_36(K‖Q)` = −0.76.
  - In both pairs the primitive arm is censored on 36–61 tasks. Its failures are cheap
    give-ups, so the comparison is not at matched accuracy and these values are lower bounds.
- **No-harm condition holds.** 0 wrong qualified answers in K and L.
- **Cached results vs capabilities:** no `derive` calls and no cached `cap:` facts. Every
  answer was computed by running a stored program.

**Reading:**
- The library's value here is reach: it learns at a small depth budget what cannot be learned
  without it.
- It is not cheaper per task once both succeed, because each capability enlarges the
  qualification scan.
- Library arm K at depth 2 makes the same decisions as C at depth 5, at about 31% of the CPU.
  Most of C's cost was the horizon of the open-world scan, not search.
