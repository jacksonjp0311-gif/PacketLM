# G47: hierarchical reuse under matched budgets (pre-registered)

Written before any G46 or G47 result was read. Same world generator, seeds (11, 22, 33),
teacher, sealed evaluation, corrections and retention as G46 (`benchmarks/g46.py`), on the
same frozen engine.

## Arms (same question budget, 4 investigations per task)

| arm | library | depth budget |
|---|---|---|
| K | on  | 2 |
| Q | off | 2 |
| L | on  | 3 |
| M | off | 3 |

From G46: C (library, depth 5) and P (no library, depth 5).

## Measures

- tasks acquired, by shape;
- sealed accuracy;
- wrong qualified answers;
- task CPU;
- candidate evaluations;
- bit-row operations;
- executions;
- maintenance CPU (correction, transfer and retention calls);
- questions asked;
- final state bytes;
- library uses.

**Cached results vs capabilities:** G46/G47 never call `derive`, so no conclusion is cached
as a fact. Every answer is computed by running a stored program, and the receipt counts
`cap:` facts to confirm this.

## Hypotheses (reported as they fall)

- **H3 (reach):** at depth 2, K acquires at least 1.5× as many tasks as Q in every seed.
  Expected from structure: 7 of the 12 task shapes need base length ≥ 3. This tests that
  reuse provides the reach, not that it is surprising.
- **H4 (cost at equal reach):** at depth 5, where both can reach every task, C costs less
  CPU per task than P (`A^reuse_36 > 0` in G46).
- **H5 (budget efficiency):** at depth 3, L's CPU per acquired task is lower than M's.
- **No-harm condition:** K and L give 0 wrong qualified answers.
  A library must not trade correctness for reach.

Maintenance overhead of the library (more programs to requalify and scan) is reported
as maintenance CPU and state bytes. It is not hidden in task cost.
