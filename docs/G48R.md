# G48R: pre-registered replication of G48 with order-independent investigate

This was written and committed before `python3 benchmarks/g48.py --seeds 491,...,497 --out g48r`
ran.

## Why

G48 (docs/G48.md, seeds 481–487) failed H6. With adaptive retention on, investigate broke ties
in fact-storage order, and a restore changed that order. After the run, programs-mode
investigate was changed to break ties by entity name (82dd0a2), with a check and a mutation.
This run tests the fixed engine on **new** seeds. G48's registered FAIL stands unchanged; this
is a separate experiment.

## Protocol

**Identical to G48:**
- the harness `benchmarks/g48.py`;
- the arms P, X, S and A;
- the world generators, teaching, the 4-question budget and refusals of sealed items;
- the metrics and the thresholds H1–H6 and source-unchanged, word for word.

**Only changes:**
- **seeds 491, 492, 493, 494, 495, 496 and 497** (S = 7), never run before;
- the engine is at the commit of this file. Since G48, the only engine change is the
  tie-break in programs-mode investigate;
- the artifact directory is `artifacts/g48r`, so the run cannot overwrite G48 evidence.

## Decision

G48R passes iff all of H1–H6 and source-unchanged hold. If H6 fails again, its mechanism is
diagnosed and recorded; the threshold is not changed.

## Results

**Registered run:** pre-registration commit 0cf4a9c. The engine sha256 starts `42e8d94c6a5d`.
Evidence is in `docs/evidence/g48r/`. Seeds 491–497.

**Verdict: 6 of 7 checks pass; H6 FAILS again, so G48R is NOT passed.**

| threshold | result |
|---|---|
| H1 | **pass**: P is 1.000 on T1 (n 434), T2 (168), T3 (126) and T4 (434) |
| H2 | **pass**: depth ≥ 3 is 1.000 (n 378); depths 6–7 are 1.000 (n 42) |
| H3 | **pass**: 0 wrong-qualified, with 14 qualified tasks (T3) and 126 qualified answers |
| H4 | **pass**: X T1–T3 is 0.000 |
| H5 | **pass**: S is 0.0017 |
| H6 | **FAIL**: seeds 493, 495 and 497 differ, in round-2 T4 investigate questions only. Programs, statuses and all 1162 answers are identical. |

The first-round results replicate G48 exactly: the same status mix and accuracy.

**H6 mechanism, second cause:**
- Investigate in programs mode scored **every** entity in the state. The acquisition's domain
  is only the observations' component.
- In P, round-2 T4's hypotheses differ on entities of other worlds, so P asked about them. In
  the state at the end of the run, 9 of P's 12 differing questions lie outside the task's
  component.
- The harness has no truth there, so those questions were refused, and the question budget
  was wasted.
- In A, those worlds were archived and absent, so A asked inside the component (12/12).
- The tie-order fix worked as intended. This is a different defect that it had been hiding.

**Rule applied:** H6 has now failed twice with one root cause: investigate depended on hot
state outside the task. I am recording it and not running a third G48 replication.
- **Fix:** programs-mode investigate scores only the observations' component, the same domain
  the acquisition uses.
- **New check:** `programs.prog_question_inside_component`.
- **New mutation:** `prog_investigate_outside_component`, killed (41/41).
- The no-harm comparison is re-tested inside the next pre-registered experiment (PX, arm RA),
  not by repeating G48.

The fix also stops P from wasting questions on other worlds. This is a cost and identifiability
improvement, observed here, that the registered thresholds did not measure.
