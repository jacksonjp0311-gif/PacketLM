# G54: exact per-call cost bounds, and whether the remaining gap is structural

Steering at 02:17 (America/New_York, 2026-11-27):
1. Pre-register a design that cuts per-call state cost (load, validation, save, `ask`) and the
   maintenance re-asks, keeping every soundness guarantee, with identical replies where the
   design claims exactness.
2. Measure it with instrument 70297af, the same controls and new seeds, at least 7 per curriculum.
3. B also pays per-call costs: report whether the remaining gap is structural.

The G45 t5 restatement is under independent review (verify-050bebd). t5 is not changed here.

## 1. Diagnosis (after G53; diagnostic, not evidence)

- **Where per-call cost goes** on the final G53 unrelated state (seed 131, 3024 facts), one
  evaluation call with 100 questions: 0.39 s under cProfile.
  - `ask` (geometric recall, every fact's packet scored per question): 0.30 s. Two `bit_count`
    calls per packet per question; the decode table (one packet per entity) is rebuilt in every
    process.
  - `validate`, run twice per process (on load and before save): 0.059 s. Each run also
    re-serializes the whole state (`sort_keys`) to check the checksum.
  - Serialization: the state is serialized three times per save (twice for checksums, once to
    write); the previous primary is copied byte for byte into the backup.
- **Fixed per-process cost** (interpreter start, imports, an empty load and save): about 27 ms,
  paid by every arm in every process, B included.
- **Maintenance re-asks** are issued by the teacher (the G46 protocol: correction, transfer and
  a retention re-ask of every earlier item, once per family). They are part of the registered
  controls, so their number is not changed here. Engine-side memoization of answers across calls
  is not exact cheaply: geometric recall depends on every stored fact. Only the per-call cost of
  those calls is targeted.

## 2. Mechanism: `--lean` (exact; same replies, same guarantees)

1. **Geometric recall with less work** (`_ask_lean`).
   - Packet.score is 2|q∧p| − |p|. If q∧p is empty the score is −|p| ≤ 0, so the packet is skipped
     exactly as before, without counting bits. |p| is counted once per packet per process.
   - The decode table is built only when some packet scores above 0.
   - Candidate order, de-duplication and the final sort are unchanged.
2. **One serialization per save** (`_save_lean`).
   - The state's canonical text (`sort_keys`) is written once, after a fixed prefix. The checksum
     is sha256 of that text, which is exactly what `_checksum` computes, so a non-lean engine opens
     the file unchanged.
   - Full validation before writing, the previous good primary kept as the backup, atomic replace
     and fsync are all kept. The backup is a hard link to the previous primary's inode (the primary
     is then replaced by a new inode) instead of a byte copy.
3. **Checksum on load from the parsed bytes** (`_lean_checksum_ok`).
   - If the exact bytes the state was parsed from hash to the stored checksum, the old check holds
     too: canonical text round-trips, and a non-canonical text with the same hash would be a
     SHA-256 collision. Any other file falls back to the old check.
4. **Fast validation** (`_valid_fast`): the same checks in the same order, without a function call
   per check. On rejection, the original `validate` runs and raises its usual message.

**What is not changed:** every decision rule, the scan, qualification, the teacher, the number of
calls, the state contents (only the key order of the saved text), full structural validation on
every load and save, and the backup and atomic-write guarantees.

**Tests:**
- Checks:
  - `g54_lean_replies_and_recall_equal`: a 120-fact world; every reply and every recall over 40
    entities × 3 relations is equal with and without `--lean`, with known and ambiguous recalls
    present.
  - `g54_lean_persistence_guarantees`: lean files open in both engines; the backup is the
    previous primary byte for byte; a structurally valid tampered primary is refused and the
    backup is loaded; an invalid state is never written.
  - `g54_fast_validation_equivalent`: 300 fuzzed documents (12 corruption kinds over real
    states); fast validation agrees with `validate` on every one, with at least 100 rejections.
- Mutations: `g54_lean_checksum_accepts_any`, `g54_lean_no_backup`, `g54_lean_save_unvalidated`,
  `g54_fast_validate_skips_premises`, `g54_fast_validate_skips_cycles`,
  `g54_lean_decode_wrong_role`.
- An equivalent mutant was dropped: accepting every packet with a non-empty overlap
  (`if not x:`) changes nothing observable, because a packet decodes to an entity only when its
  subject and relation equal the query's, and then it scores above 0. The score test is kept
  as in the original path.

## 3. Pre-registered measurement

- **Harness:** `benchmarks/g54.py`. Teacher, cost and instrument as G53 (G50 `complete` teacher,
  whole-process CPU with maintenance, 70297af unmodified, 5000 bootstrap resamples).

| arm | flags | role |
|---|---|---|
| Cb | `--answers --bounded` | persistent library learner, G53 engine path (reference for the mechanism) |
| Cl | `--answers --bounded --lean` | persistent library learner, lean |
| Bb | `--answers --no-library --bounded` | empty state per task, G53 path (for B's own change) |
| Bl | `--answers --no-library --bounded --lean` | empty state per task, lean (reference learner for L1, L3) |
| Pl | `--answers --no-library --bounded --lean` | persistent, primitive-only |
| Fl | `--answers --bounded --lean` | frozen after phase A (compositional only) |

The reference learner gets the same per-call bounds (Bl), so L1 and L3 compare like with like.

**Seeds** (new): compositional (G46 worlds, n = 36) **141–147**; unrelated (G46-U, n = 24)
**151–157**.

**Command:** `python3 benchmarks/g54.py --out g54`

**Contrasts:** A(Cl+maint ‖ Bl) (L1, L3), A(Cl+maint ‖ Pl+maint) (L2), A(Cl+maint ‖ Cb+maint)
(M), A(Bl ‖ Bb), A(Cl ‖ Bl), A(Cl ‖ Pl), and A(Cl+maint ‖ Fl+maint) on the compositional
curriculum.

**Decision rules (fixed now):**

| rule | what is claimed, and when |
|---|---|
| **M** | A saving is claimed on a curriculum only if the lower bound of A(Cl+maint ‖ Cb+maint) is > 0 |
| **L1** | Learning-to-learn on the compositional curriculum only if the lower bound of A(Cl+maint ‖ Bl) is > 0 |
| **L2** | Reuse only if the lower bound of A(Cl+maint ‖ Pl+maint) is > 0 |
| **L3** | On the unrelated curriculum, if the upper bound of A(Cl+maint ‖ Bl) is < 0, the utility problem persists |
| **S (structural, descriptive)** | Floor f0 = median whole-process CPU of 40 Bl-flag calls on an empty state with one question. Each arm's cost splits into processes × f0 (structural) and the rest. Two numbers per curriculum: (a) A_struct = 1 − (processes_Cl × f0 + above-floor_Bl) / total_Bl, the A(Cl+maint ‖ Bl) the run would show if Cl did no more work per call than Bl; (b) the structural share of the gap, (processes_Cl − processes_Bl) × f0 / (total_Cl − total_Bl). **If A_struct < 0, the floor binds:** the protocol's process count alone keeps the persistent learner costlier, whatever its per-call work. **If the share is ≥ 0.5, the remaining gap is mostly structural;** otherwise it is mostly per-call work above the floor. |

**Guards (run validity):** Cl's reply stream hash-equals Cb's, and Bl's equals Bb's, on every
seed; 0 wrong-qualified sealed answers in Cb and Cl; the instrument is pinned and unmodified;
every report ran; source unchanged. If an exactness guard fails, the mechanism is not exact: the
run is invalid for M and nothing is claimed.

## 4. Dev run (seeds 961–964; not evidence)

- **Run:** `python3 benchmarks/g54.py --dev --comp-seeds 961,962 --unrel-seeds 963,964`
  (receipt `docs/evidence/g54/g54_dev_receipt.json`). It ran while the test suite was also
  running, so absolute times are noisy. The structural share was added to the harness after it
  and is computed here by hand from the receipt. An earlier one-seed dev (961/963) and the
  profile `docs/evidence/g54/profile_lean_Cl_Bl.json` were taken before fast validation.
- **Guards:** all held; Cl equals Cb and Bl equals Bb on all 4 seeds.
- A_n = 1 − C_cont/C_base; cost ratio = 1 − A.

| curriculum | Cb | Cl | Bb | Bl | Pl | Fl |
|---|---|---|---|---|---|---|
| comp, whole CPU (s) | 28.7 | 24.6 | 14.1 | 13.6 | 19.5 | 8.8 |
| comp, processes | 301 | 301 | 256 | 256 | 304 | 208 |
| unrel, whole CPU (s) | 22.2 | 14.9 | 3.5 | 3.4 | 14.8 | – |
| unrel, processes | 256 | 256 | 112 | 112 | 256 | – |

- **Compositional:** A(Cl+maint ‖ Cb+maint) = +0.144; A(Cl+maint ‖ Bl) = −0.810 (1.81×);
  A(Cl+maint ‖ Pl+maint) = −0.262; A(Bl ‖ Bb) = +0.037.
- **Unrelated:** A(Cl+maint ‖ Cb+maint) = +0.331; A(Cl+maint ‖ Bl) = −3.386 (4.39×);
  A(Bl ‖ Bb) = +0.038.
- **Structure** (f0 = 26.3 ms):
  - comp: A_struct = −0.087, share ≈ 0.11 (the floor binds slightly; the gap is mostly the scan
    and state work above the floor);
  - unrel: A_struct = −1.116, share ≈ 0.33 (the floor binds: 256 processes × 26.3 ms = 6.7 s is
    already about twice Bl's whole cost; the rest is whole-state load, parse, validation and save
    above the floor).

**Prediction:** M holds on both curricula; L1 and L2 no claim; L3 holds; on the unrelated
curriculum the floor binds (A_struct < 0) but the gap is not mostly structural (share < 0.5);
on the compositional curriculum A_struct is near 0 and the share is small.
