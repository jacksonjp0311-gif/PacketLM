# G58: exact capability routing (`--routed`), Roadmap II: adaptive capability economics

Registered before the run (2026-11-27; this text is final at the commit that adds it, before any G58
registered run). The registered run starts only with `/workspace/REGISTERED_RUN.lock` in place (start
time, experiment name), with no other CPU work of ours beside it, and the lock is removed right after
(`benchmarks/g58_registered.sh` records the create and delete times). Every arm run is written to disk
when it finishes.

## 1. Why

G57b removed state-proportional work for unrelated *facts*. Unrelated *capabilities* still cost:
on a library-padding dev workload (`benchmarks/g58_dev_partl.py`, dev seed 991), the G57b engine
(`--indexed --incremental`, commit 8994490) spends 2.75 ms per task with no library and 131 ms with
1,024 unrelated capabilities (10.6 ms at L = 64). The costs are per-call loops over the whole
library: `review` re-evaluates every capability on each observation; `primitives` rebuilds the
offered list; the scan and activation rebuild per-primitive tables; `_flush_growth` tests every
qualified capability's region; `_basis` serializes the offered list.

## 2. Mechanism: `--routed` (requires `--indexed`, geometry, static retention; no programs/operators)

The flag changes no reply and no state byte (checked: §3). Each part below says what is skipped and
why skipping it cannot change the outcome.

**2a. Review routing (`_review_routed`).** `evaluate(seq, obs)` is a function of its fingerprint
(`_review_fp`): the version (number, status, seq), the status of every version in its dependency
closure (`expand` returns None unless all are pinned-OK), the expanded base relations and each one's
change stamp (`execute` reads only those relations' triples), and per observation the subject, the
value, whether the subject is a known entity and whether it is closed (`complete`). A capability is
re-evaluated only when its fingerprint may differ from the one of its last non-contradicted
evaluation. Candidates (a superset of the changed fingerprints): capabilities whose observations
changed, that read a relation whose stamp moved, whose status or versions changed, whose closure
holds a version whose status changed (dependency map), whose observed subjects changed closed-world
status or became known/unknown (entity-set delta; added after the contract fuzz found it, seed
5821), and new capabilities. They are visited in capability order; if a status changes during the
pass, every later capability is visited with its full fingerprint, and the next review is a full pass.
Outcome: the same evaluations' results, the same suspensions in the same order.

**2b. Capability index (`_cx`).** Per capability: offered or not (the `_offered` test), its
primitive, base, first base relation and closure names; the offered names in name order; per first
relation the offered names with a defined base; per name the offered capabilities whose closure
holds it. It is synced from the names written since the last sync (status changes, new versions)
plus every capability whose closure holds one of them (its base depends on their statuses); it is
rebuilt when the capability records object or the library flags change. From it:
- `primitives(name)` = relation primitives + the offered list minus the name and the capabilities
  that would form a cycle (the same list `_offered`'s loop builds);
- the bounded scan and the activation walk get, per node, the primitives whose base starts with a
  relation that leaves the frontier, in `primitives` order (relations, then capabilities by name).
  These are exactly the ones the G53/G57b by-first-relation tables yield for that node; the others
  have an empty image whatever the path (relevance-pruned) and were already never visited in bounded
  mode, so the scan's counts (scanned, duplicates, pruned, blockers), the chosen program and its
  qualification status are those of the full table. In activation, each skipped primitive adds
  P^(n-len-1) to `pruned`, as before. Pruned capabilities therefore cannot change a scan's outcome.

**2c. Growth routing (`_flush_growth_routed`).** A version's region is its seeds (domain and observed
subjects) plus the union-find classes of the seeds; it is re-acquired when a grown entity is in it.
A grown entity is in a region only if it is a seed or shares a class with one, so the candidates are
the names indexed (seeds index `_sx`) at the grown entities and at every member of their classes
(class members tracked with the union-find). They are taken in name order with the same test as the
full loop; after each re-acquisition the candidates are recomputed and only later names are taken,
as the loop would.

**2d. Audit (tests only).** `engine.G58_AUDIT`: when on, every shortcut is recomputed the unrouted
way at each use and any difference is logged — every unvisited capability has its recorded
fingerprint and no capability left executable is contradicted; `_expand_fast`, `_closure_cached`,
`_routing`, the offered list, every index entry, every scan/activation visit list, `_reach`, and the
growth candidates. Off in every registered run.

**2e. Not done (decisions, with evidence).**
- *(2) relevance-scoped requalification* (`_fc_requalify` only when the version's dependency region
  changed): measured, not implemented. On the dev comp curriculum (seed 961) there are 37 fc
  re-acquisitions, 30 with an unchanged fact epoch, and 0 where every changed input lay outside the
  region; on unrel there are 0. It has no target in the registered curricula, and since
  re-acquisition records (turn, counts) are state bytes, skipping one cannot be byte-exact — only
  decision-exact. Queued, not claimed.
- *(3) evidence-gated capability-retention economics*: not done (optional; would be a separate,
  non-exact arm with accuracy reported). Queued.
- `_basis` still serializes the offered list (O(L) at C speed); the review fingerprint gate,
  hypothesis enumeration and snapshot validation still scale with the library.

## 3. Exactness evidence (before registration)

- `packetlm/g58_diff.py`: replies and state compared after every call, final snapshots byte-compared,
  `--routed` against `--indexed --incremental`, with the audit on; 10 directed scenarios + random
  sessions (completes, examples at unknown entities, corrections, compositions, requalify). Seeds
  581 and 5801–5816: 0 differences, 0 audit violations.
- `g58_diff.contract_fuzz`: after every call, arbitrary status transitions (any status to any),
  corrected examples, observations, re-acquisitions and corrected facts applied directly, each
  followed by `review`; every shortcut exercised on every version. Seeds 582, 5820–5849: 0 violations.
- Recorded dev arms (comp 961, unrel 961) replayed with `--routed`: identical reply and state hashes.
- Library scaling dev (seeds 991–992): j and r replies and states equal the 8994490 checkout's.

## 4. Registered: library-size scaling (`benchmarks/g58_libscale.py`)

- Seeds 261–267 (fresh), L ∈ {0, 64, 256, 1024} unrelated capabilities, 10 tasks, the workload of §1.
  Arms: **j0** = the 8994490 checkout itself (`--indexed --incremental`; subprocess with that tree on
  sys.path), **j** = this commit without `--routed` (reported), **r** = `--routed`. Charged: workload
  call CPU per task; padding and a snapshot outside the window; final snapshot measured separately.
- Statistic: per seed R64_1024 = mean task CPU at L = 1024 / at L = 64, and R0_1024 (/ L = 0);
  mean and 95% bootstrap CI over seeds (5000 resamples, seed 0).
- **Stop rule (anti-circling), registered:** material iff Xr R64_1024 upper CI ≤ half of j0's
  R64_1024 point estimate **and** Xr R0_1024 upper CI ≤ half of j0's R0_1024 point estimate, in the
  same run. Otherwise stop and report (no further routing work in G58).
- **Flatness threshold, registered:** flat iff Xr R64_1024 upper CI ≤ 1.25 (R0 form reported).
- Guards: every j and r reply stream and final state equal j0's at every (seed, L); the workload's
  answered count is the same at every L; no snapshot in the timed window; j0 is a clean 8994490.

  271–277, unrel seeds 281–287 (fresh; ≥ 7 per curriculum), arms Xj (`--indexed --incremental`) and

  (solved, qualified, library use, wrong-qualified) reported separately per arm.
- Guards: every Xr reply stream and final state byte-identical to its Xj twin; 0 wrong-qualified in
  C; instrument pinned and unmodified; source unchanged during the run.
