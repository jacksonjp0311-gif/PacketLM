# G45 — one teachable conversational machine

Written before `packetlm/g45_test.py` is run.

## Interface (controlled language, not open natural language)

`Engine.turn` is the only entry for people (`python -m packetlm.chat --interactive`),
scripts (`python -m packetlm.engine STATE 'line' ...`), `chat.run` and tests.

| Teaching | Command |
|---|---|
| fact | `fact S R O`, or a sentence read through a learned construction |
| construction | `construct M: <3-word sentence> = S O; ...` |
| question form | `question R: <words with the subject> = S; ...` |
| vocabulary | `define WORD as RELATION` |
| example | `example NAME: S -> O` (records it, then re-runs acquisition) |
| correct an example | `correct example NAME: S -> O` |
| acquire / requalify | `learn NAME` |
| ask | `what is S R`, or a learned question form |
| clarify | ambiguous answers list the candidates; `investigate NAME` returns the engine's next question; `unanswered NAME: S` when the teacher cannot answer |
| explain | `why S R` |
| inspect | `show NAME`, `capabilities` |
| correct / retract | `correct S R O`, `retract S R [O]`, `revoke NAME` |
| save / resume | every CLI call loads, validates, runs and saves atomically |

## Qualification protocol (`g45_test.py`)

- Seeds 101, 202, 303. Each starts from an empty state file.
- Six generated domains per seed. Relation and entity names are random strings,
  so no domain words appear in the source. Each relation is a random function
  between layers of 12 entities. Two distractor relations per domain.
- Hidden programs, one per domain, held only by the harness (the "teacher"):
  D1 `a+b`, D2 `a+a`, D3 `b+a`,
  D4 `a+b` with a distractor `d` equal to `a` on the first examples
  (needs investigation),
  D5 `D1-capability + e` (three base steps; needs the library at depth 2),
  D6 `b+c` with missing `b` facts for some subjects (undetermined handling).
- Teaching per domain is one fresh process: a random-order construction for
  relation `a` (facts of `a` are taught as sentences), `fact` for the rest,
  then 2 examples. While the result is not `qualified`, the harness runs
  `investigate`, answers the engine's question from the hidden program, and
  repeats (budget 6). Every call is a new process.
- Withheld evaluation: all layer-0 subjects not used as an example or a
  question, plus a transfer graph. A later session teaches new entities for
  D1's relations, and the D1 capability is asked about them. Truth comes from
  `reference.run` over the generated graph.
- Retention: a final fresh process re-asks every evaluation question.

## Pre-registered thresholds (per seed)

1. At least 5 of 6 domains acquire a capability whose base program equals the
   hidden program (by relation identity).
2. Zero wrong answers on withheld subjects from capabilities marked `qualified`.
3. Coverage of at least 0.9 (answered / truth-defined) on withheld subjects for each
   acquired capability. Provisional answers are counted and reported separately.
4. Transfer: D1 on the new graph, zero wrong and coverage of at least 0.9.
5. Retention: final-process answers are identical to the answers given
   right after acquisition.
   *Restated in G53 (1932326, docs/G53.md §2b), after the S1 soundness fix of verify-cdb4828; the
   original result above is unchanged.* Told facts added inside a qualified capability's region
   now re-run its scan, so a later domain built on D1's world demotes D1 to provisional on all
   three seeds. Criterion 5 now reads: every re-asked value is identical, and every changed reply
   is the same value marked provisional, of a capability re-scanned to provisional with blockers.
   The strict "identical" reading fails on 101, 202 and 303 and is kept in the receipt
   (`retention_strict_identical`). verify-050bebd judged the restatement legitimate; its five
   retention-loss mutations are in `packetlm/mutations.py` (`G45_MUTATIONS`).
6. Engine source sha256 is identical before and after all sessions (no source change).
7. Controls: (a) shuffled examples (answers permuted across subjects)
   acquire the hidden program in at most 1 of 6 domains;
   (b) `--no-library` fails to acquire D5 at depth 2.

Any threshold miss means G45 stays HOLD; the result is reported, not tuned.

## Result (engine sha256 8be3afc2…, `python -m packetlm.g45_test`)

All 18 pre-registered checks pass (3 seeds × 5, plus t6, t7a, t7b).

| seed | domains matched | wrong (qualified) | withheld answered/defined | transfer | retention | processes | engine CPU |
|---|---|---|---|---|---|---|---|
| 101 | 6/6 | 0 | 57/57 | 12/12 | 72 identical | 17 | 1.30 s |
| 202 | 6/6 | 0 | 57/57 | 12/12 | 72 identical | 17 | 1.34 s |
| 303 | 6/6 | 0 | 57/57 | 12/12 | 72 identical | 19 | 1.56 s |

- Examples used per domain: 2, or 3 where the engine asked one question
  (D4 in all three seeds, where it was confounded on purpose; D6 in seed 303).
- Controls:
  - Shuffled examples: 0/6 hidden programs in every seed. Seed 101 still
    *qualified* a wrong program in D6, from 2 shuffled examples, and gave 5 wrong
    answers. Qualification can only be as good as the evidence.
  - `--no-library`: D5 is not acquired at depth 2 in 3/3 seeds
    (30 candidates evaluated).
- **Observation (cost of accumulation):** candidate evaluations per domain rise
  20 → 89 → 207 → 376 → 457 → 696 as relations from earlier domains join the
  primitive set. Accumulated knowledge makes later search *more* expensive under
  this unindexed enumeration. This is a direct negative for the learning-to-learn
  hypothesis unless relevance routing is added. It is recorded for G46/G47.
- State size about 1.06 MB per seed, mostly stored zero-support hypotheses (audit item 1).

Limits: generated functional graphs with 12 entities per layer; procedures are
relation compositions of depth ≤ 3; controlled language only; the harness
plays the teacher.
